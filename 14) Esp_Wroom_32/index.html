Recursos del SoC

Pines que exigen cuidado

  • GPIO6–11: conectados a la flash interna. Usarlos cuelga el chip.
  • GPIO34–39: solo entrada, sin pull-up ni pull-down internos.
  • Strapping (0, 2, 5, 12, 15): su nivel al reset define el modo de arranque. GPIO12 en alto puede poner la flash a 1.8 V y dejar el módulo sin arrancar.
  • ADC2: no disponible mientras el Wi-Fi está activo.
  • GPIO1/3: UART0, usada para programar y para el monitor serie.

Límites eléctricos

  • Lógica a 3.3 V. Los pines no toleran 5 V.
  • Corriente por pin: hasta ~40 mA (recomendado ≤ 20 mA).
  • Alimentación 3.0–3.6 V; picos de ~500 mA al transmitir por Wi-Fi.
  • Deep sleep: ~10 µA con el temporizador RTC.
  • Solo los pines RTC pueden despertar al chip del deep sleep (ext0/ext1, touch).

Módulo 04 · Tiempo real

Interrupciones, rutinas y corrutinas

Una interrupción detiene lo que hace la CPU para ejecutar una rutina de servicio (ISR). Pulsa el botón simulado y compara una ISR ligera, que solo levanta una bandera, con una ISR pesada que bloquea al resto del sistema.

Reglas de una buena ISR

  • Marcarla con IRAM_ATTR para que resida en RAM interna y no dependa de la caché de flash.
  • Ejecutar en microsegundos: leer, guardar y salir. Nada de delay(), Serial.print() ni malloc().
  • Variables compartidas declaradas volatile y protegidas con portENTER_CRITICAL_ISR.
  • Delegar el trabajo con xQueueSendFromISR o xTaskNotifyFromISR a una tarea.
  • Filtrar rebotes por tiempo o por hardware (RC + Schmitt trigger).
  • Fuentes en el ESP32: flancos o niveles de GPIO, temporizadores, UART, touch, RTC, watchdog.

Código de referencia

Arduino / ESP-IDF
QueueHandle_t q;
volatile uint32_t ultimo = 0;

void IRAM_ATTR isrBoton() {
  uint32_t t = millis();
  if (t - ultimo < 50) return;       // antirrebote
  ultimo = t;
  BaseType_t woken = pdFALSE;
  xQueueSendFromISR(q, &t, &woken);
  if (woken) portYIELD_FROM_ISR();
}

void tareaBoton(void*) {
  uint32_t t;
  for (;;) if (xQueueReceive(q, &t, portMAX_DELAY))
    Serial.printf("Pulsación a %lu ms\n", t);
}

void setup() {
  q = xQueueCreate(10, sizeof(uint32_t));
  pinMode(0, INPUT_PULLUP);
  attachInterrupt(0, isrBoton, FALLING);
  xTaskCreatePinnedToCore(tareaBoton, "btn", 2048, NULL, 5, NULL, 1);
}

Módulo 05 · FreeRTOS SMP

Hilos y buen uso del doble núcleo

El ESP32 tiene dos núcleos: PRO_CPU (núcleo 0), donde ESP-IDF ejecuta la pila Wi-Fi/Bluetooth, y APP_CPU (núcleo 1), donde Arduino ejecuta loop(). Cambia la estrategia de asignación y observa la carga y los plazos incumplidos.

Buenas prácticas con dos núcleos

  • Deja el núcleo 0 para Wi-Fi, BT y lwIP; fija el control determinista (PID, muestreo) al núcleo 1.
  • Asigna prioridades por urgencia: el lazo de control por encima de la telemetría.
  • Comunica tareas con colas (xQueueSend) en vez de variables globales.
  • Protege recursos compartidos (I²C, SPI, Serial) con mutex; los mutex de FreeRTOS heredan prioridad y evitan la inversión de prioridad.
  • Entre núcleos, una sección crítica necesita portMUX_TYPE con portENTER_CRITICAL; deshabilitar interrupciones en un núcleo no detiene al otro.
  • Nunca uses espera activa: vTaskDelay o vTaskDelayUntil ceden la CPU.
  • Dimensiona la pila y vigila uxTaskGetStackHighWaterMark; deja activo el watchdog de tareas.

SemaphoreHandle_t i2cMutex;
QueueHandle_t qLecturas;

void tareaControl(void*) {            // núcleo 1
  TickType_t t0 = xTaskGetTickCount();
  for (;;) {
    if (xSemaphoreTake(i2cMutex, pdMS_TO_TICKS(5))) {
      float v = leerSensorI2C();

MicroPython: hash, AES y firma de lectura
import hashlib, cryptolib, os, ubinascii, json

clave = os.urandom(32)                     # TRNG del ESP32
iv = os.urandom(16)
dato = json.dumps({"temp": 24.5}).encode()
dato += b" " * (16 - len(dato) % 16)          # relleno a bloque
aes = cryptolib.aes(clave, 2, iv)          # 2 = modo CBC
cifrado = aes.encrypt(dato)

h = hashlib.sha256(cifrado).digest()
print(ubinascii.hexlify(h))

# Mini prueba de trabajo
def minar(prev, datos, dif=3):
    n = 0
    while True:
        s = "{}{}{}".format(prev, datos, n).encode()
        hx = ubinascii.hexlify(hashlib.sha256(s).digest())
        if hx[:dif] == b"0" * dif:
            return n, hx
        n += 1
Arduino: AES-GCM con mbedTLS (acelerado)
#include "mbedtls/gcm.h"
#include "esp_random.h"

uint8_t key[32], iv[12], tag[16], out[64];
const char* msg = "{\"temp\":24.5}";

void cifrar() {
  esp_fill_random(key, 32);
  esp_fill_random(iv, 12);
  mbedtls_gcm_context g;
  mbedtls_gcm_init(&g);
  mbedtls_gcm_setkey(&g, MBEDTLS_CIPHER_ID_AES, key, 256);
  mbedtls_gcm_crypt_and_tag(&g, MBEDTLS_GCM_ENCRYPT, strlen(msg),
      iv, 12, NULL, 0, (const uint8_t*)msg, out, 16, tag);
  mbedtls_gcm_free(&g);
  // enviar iv + out + tag por MQTT/ESP-NOW
}
Módulo 08 · Profundización en tareas

asyncio en MicroPython

Un solo hilo, un ciclo de eventos y varias corrutinas que ceden el control en cada await. Crea tareas, páusalas, reanúdalas o cancélalas; quita el Lock para ver cómo dos tareas mezclan sus mensajes en la UART, e inyecta un time.sleep() para congelar el ciclo completo.

Ciclo de eventos

Mantiene una cola de tareas listas y otra de tareas dormidas ordenadas por hora de despertar. Ejecuta una tarea hasta su siguiente await y pasa a la siguiente.

asyncio.create_task()

Envuelve una corrutina en una tarea y la agenda de inmediato. Devuelve el objeto Task que luego se puede esperar o cancelar.

Pausar, reanudar, cancelar

No existe task.pause(): se pausa esperando un asyncio.Event. task.cancel() lanza CancelledError en el siguiente await.

asyncio.Lock()

Con async with lock: solo una tarea usa el recurso; las demás esperan sin bloquear el ciclo y el lock se libera aunque la tarea sea cancelada.

Multitarea cooperativa

Nadie interrumpe a una corrutina: si no llega a un await, ninguna otra tarea avanza. Por eso se usa await asyncio.sleep_ms(), nunca time.sleep().

import asyncio
from machine import Pin, ADC

uart_lock = asyncio.Lock()
continuar = {}                               # un Event por tarea pausable

async def punto_de_pausa(nombre):
    await continuar[nombre].wait()          # bloquea solo esta tarea

async def leer_sensor():
    adc = ADC(Pin(34))
    while True:
        await punto_de_pausa("sensor")
        print("[sensor]", adc.read_uv() // 1000, "mV")
        await asyncio.sleep_ms(700)

async def escribir_uart(nombre, texto):
    try:
        while True:
            await punto_de_pausa(nombre)
            async with uart_lock:              # sección crítica cooperativa
                for i in range(0, len(texto), 4):
                    uart.write(texto[i:i+4])
                    await asyncio.sleep_ms(15)    # cede: aquí otra tarea podría colarse
                uart.write("\n")
            await asyncio.sleep_ms(400)
    except asyncio.CancelledError:
        print("limpieza de", nombre)           # el lock ya se liberó
        raise

async def main():
    for n in ("sensor", "mqtt", "log"):
        continuar[n] = asyncio.Event(); continuar[n].set()
    t1 = asyncio.create_task(leer_sensor())
    t2 = asyncio.create_task(escribir_uart("mqtt", "MQTT planta/temp=24.5"))
    t3 = asyncio.create_task(escribir_uart("log", "LOG nivel=INFO ok"))
    await asyncio.sleep(5)
    continuar["sensor"].clear()               # pausar
    await asyncio.sleep(3)
    continuar["sensor"].set()                 # reanudar
    t3.cancel()                                 # cancelar
    await asyncio.gather(t1, t2)

asyncio.run(main())
